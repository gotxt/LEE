# 새 기믹 개발 작업의 첫 프롬프트

같은 프로젝트 `C:/GameMake/Unity6/LEE`를 연결한 새 Codex 작업에 아래 코드 블록을 붙여 넣는다. 이 파일과 [개발 가이드](NewMechanicGuide.md), 최신 미커밋 코드/에셋이 새 작업에서도 보이는지 확인한다. 새 worktree가 HEAD에서 시작되면 아직 커밋하지 않은 기믹 기반 구조가 빠질 수 있다.

맨 아래 ‘만들 기믹’ 부분만 아는 만큼 채우면 된다. 아직 정하지 않은 것은 미정으로 두고 설계부터 함께 정한다. 이 프롬프트는 첫 응답에서 바로 구현하지 않고 실제 구조 확인과 설계 협의를 시작하도록 구성했다.

```text
이 작업에서는 Unity 6 게임 Trace Strike에 기존 수정 봉인과 다른 규칙을 가진 새 보스 기믹을 설계하고 구현할 거야. 이전 채팅 내용을 알고 있다고 가정하지 말고 현재 프로젝트 파일을 기준으로 작업해줘.

프로젝트: C:/GameMake/Unity6/LEE
기준 Unity: 6000.5.3f1 — ProjectSettings/ProjectVersion.txt에서 다시 확인해줘.

먼저 아래 문서를 읽어줘.
1. C:/GameMake/Unity6/LEE/Docs/MechanicHandoff/NewMechanicGuide.md
2. C:/GameMake/Unity6/LEE/Docs/BossMechanics.md
3. C:/GameMake/Unity6/LEE/Docs/PatternHandoff/GameOverview.md

개별 공격을 제작할 때는 Docs/PatternHandoff/PatternAuthoringGuide.md와 CurrentPatternCatalog.md도 읽어줘. 오래된 문서와 현재 파일이 다르면 코드/에셋으로 확인하고 차이를 알려줘.

git status와 대상 diff부터 확인하고, NewMechanicGuide.md의 소스 목록을 따라 Definition/Runtime/Session, 실제 게임 연결, 기믹 에디터와 미리보기, 기존 테스트를 확인해줘. 미커밋 신규 파일도 현재 구현이므로 보존해줘. 별도 worktree에 핵심 구조가 없으면 구형 시스템을 새로 만들지 말고 누락부터 알려줘. 같은 에셋을 다른 작업이나 Unity 에디터와 동시에 덮어쓰지 말아줘.

목표:
- 새로운 규칙은 재사용 가능한 BossMechanicDefinition / BossMechanicRuntime으로 구현한다.
- 위치, 개수, 시간, 외형, 연결 공격 등 팀원이 바꿀 요소는 기존 보스 패턴 에디터에서 편집 가능하게 한다.
- 기믹의 개별 공격은 기존 시간축 패턴을 연결해 계속 편집할 수 있게 한다.
- 여러 보스/페이즈에서 사용할 수 있도록 하고 보스 이름이나 ID로 동작을 하드코딩하지 않는다.

중요한 작업 원칙:
- 먼저 규칙과 상태 전이, 기존 구조로 가능한 부분, 새 연결이 필요한 부분, 에디터 조작, 검증 계획을 설명해줘. 설계 승인 후 구현하자.
- 현재 지원하지 않는 이동 이벤트, 순서 있는 경로 전달, HP 조건, 패턴 신호 전달이 이미 있다고 가정하지 마. 필요한 경우 게임과 프리뷰, 수명/해제, 테스트까지 포함한 최소 확장안을 제안해줘.
- 기믹 추가 메뉴/기본 필드 자동 표시와 지도 클릭 배치 UI는 다른 기능이야. 새 기믹에 지도 편집이 필요하면 그 UI까지 구현 범위에 넣어줘.
- Definition에 실행 상태를 저장하지 말고, 장치별 공격 원점과 자원 소유를 분리해줘. 종료/사망/재시작/페이즈 전환/예외 시 오브젝트·공격·구독이 남지 않게 해줘.
- 기존 크림슨 골렘의 맵, 스폰, START/END 영역, 외형, 패턴, 수정 봉인을 승인 없이 바꾸지 마. 특히 마지막 수정 해제 공격은 보스 HP 1을 남기고 다음 공격부터 처치하는 규칙을 보존해줘.
- 대상을 정하지 않았으면 새 기믹을 크림슨 골렘에 임의로 연결하거나 새 보스를 자동 생성하지 마. 대상 콘텐츠와 변경 범위를 먼저 합의해줘.
- 기존 보스 데이터를 생성기로 재생성하지 말고 ID/GUID/managed-reference 연결과 사용자 변경을 보존해줘.
- 실제 수행한 컴파일·직렬화·Undo·규칙·페이즈 통합 검증과 미검증 사항을 구분해줘. 과거 통과 기록을 새 결과로 쓰지 말고, 테스트를 위해 사용자 콘텐츠를 임의로 되돌리지 마.
- 사용 중인 Unity를 닫지 말고 필요하면 최신 파일을 담은 격리 사본에서 검증해줘. 렌더링 검사에 그래픽 장치가 필요하다는 점도 고려해줘.
- 구현 완료 후 팀원용 사용법, 변경된 확장 계약과 테스트 결과를 문서화해줘.

만들 기믹:
- 대상 보스 / 페이즈: [미정이면 미정]
- 원하는 동작 설명: [플레이어가 무엇을 해서 어떤 결과를 얻는지 자유롭게 작성]
- 시작 조건: [예: 페이즈 진입 즉시 / 미정]
- 성공 조건 / 실패 조건 및 결과: [미정 항목은 질문해줘]
- 보스 피해·처치와의 관계: [보호 여부, 해제 공격 처리 등]
- 배치할 장치·영역과 준비된 리소스: [개수/위치/외형 등 아는 범위]
- 에디터에서 수정하고 싶은 요소: [아는 범위]
- 기존 콘텐츠 변경 허용 범위: [기본은 기존 콘텐츠 유지]

첫 응답에서는 파일을 수정하지 말고 실제 구조 이해와 이 기믹의 설계안을 간단히 정리해줘. 위 기믹 설명이 비어 있다면 임의의 기능을 만들지 말고 필요한 설명부터 요청해줘. 기획에서 결과를 바꾸는 미정 사항만 질문하고, 내가 승인하면 구현·검증·사용 문서 작성까지 진행해줘.
```

## 다음 메시지로 규칙을 설명하는 예시

아래는 새 기믹의 기획 예시이지 구현된 기능이 아니다.

```text
장치 3개를 정해진 순서대로 작동시키는 기믹을 생각 중이야.
완성된 경로 공격에 다음 차례 장치를 포함하면 한 단계 진행하고,
잘못된 장치를 포함하면 진행도를 초기화했으면 해.
한 경로에 여러 장치가 들어갔을 때의 처리와 성공 보상은 아직 미정이야.
장치 위치와 순서, 실패 시 공격은 에디터에서 바꿀 수 있으면 좋겠어.
대상 보스는 아직 정하지 않았으니 기존 크림슨 골렘은 수정하지 말고 설계부터 하자.
```
