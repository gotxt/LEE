# 기믹 출력 값으로 여러 위치에서 패턴 호출

2026-09-28 · Unity 6000.5.3f1.

기믹이 제공하는 **이름 붙인 위치 목록**을 패턴 이벤트에서 선택한다. 보스/기믹 타입을 검사하는 분기가 없으며, 같은 종류의 기믹을 여러 개 배치해도 연결 ID로 구분한다. 이번 소비 이벤트는 위치 목록을 사용한다. 숫자·불리언 조건을 모든 이벤트에 연결하는 범용 노드 편집기나 문자열 명령 실행기는 아니다.

## 제공하는 값

| 기믹 | 에디터 출력 이름 | 안정적인 출력 키 |
|---|---|---|
| 구역 씨앗 성장 | 완전 성장체 위치 | `mature-positions` |
| 수정 봉인 | 활성 수정 위치 | `active-positions` |

씨앗은 **완전 성장체만** 제공한다. 미성장 씨앗은 제외되며 호출 후 성장한 씨앗은 다음 호출부터 참여한다. 수정은 현재 코드의 `Device.Active` 상태를 사용한다. 기존 수정의 개별 자동 반복 공격은 유지되므로, 출력을 추가 호출하면 기존 자동 공격과 겹칠 수 있다.

## 팀원용 제작 순서

1. 재사용 패턴에 **성장체 주변 공격** 같은 이름으로 자식 패턴을 만든다. 각 성장체가 공통으로 사용할 공격이다.
2. 자식의 간편 공격 설계에서 위치 기준을 **기믹 / 호출 위치**로 선택하고 주변 타일을 칠한다. Warning/Damage/VFX는 기존처럼 한 공격의 영역 키를 공유한다. 경고 길이·타격·VFX·다음 공격 시간표도 여기서 수정한다.
3. 실제 페이즈의 주 패턴 또는 반복 배경 패턴을 열고 **고급 이벤트 편집 → 이벤트 추가 → 기믹 → 기믹 위치에서 패턴 호출**을 선택한다.
4. 선택 이벤트 아래 **Encounter Pattern**에 자식 패턴, **값을 제공할 기믹**에 해당 씨앗 기믹, **위치 출력 값**에 **완전 성장체 위치**를 선택한다. 같은 이름의 기믹도 페이즈와 목록 번호로 구분할 수 있다.
5. 호출 이벤트의 시작 시간을 정한다. 지속 시간은 자식 패턴 전체 길이 이상이어야 한다. 패턴을 선택하면 필요한 길이까지 자동으로 늘어나지만, 이후 자식 길이를 늘렸다면 호출 구간도 다시 확인한다.
6. **저장**한다. 기믹 ID는 최초 연결 시 발급되어 보스 에셋에 저장된다. 기존 미연결 기믹이나 다른 보스의 데이터를 자동 수정하지 않는다.

공격 범위를 바꾸려면 자식 하나만, 호출 시각을 바꾸려면 부모의 호출 이벤트를 수정한다. 여러 기믹을 한 시간표에서 쓰려면 호출 이벤트를 각각 추가하고 같은 시각 또는 다른 시각에 놓는다.

기존 ‘기믹 / 호출 위치’ 자체가 씨앗을 찾아 주는 것은 아니다. **호출하는 쪽에서 기믹 출력 값을 선택**해야 한다. 자식에 Player/Absolute 등 다른 기준을 쓰면 그 기준이 적용된다. 공유 위치 그룹도 일반 위치 기준보다 우선하므로 확인한다.

## 호출 규칙과 수명

- 이벤트 시작 순간 위치 목록을 한 번 복사·중복 제거·정렬한다. 위치마다 독립 PatternContext/PatternRunner로 같은 자식을 동시에 시작한다. 다른 위치의 영역 키/소환물 키가 섞이지 않는다.
- 실행 중 기믹 상태가 바뀌어도 이번 공격의 원점 목록은 유지한다. 경고 도중 대상을 추가하거나 재조준하지 않는다. 완전 성장체는 원래 파괴 불가이므로 제거 취소 규칙을 추가하지 않았다. 다른 기믹도 이 이벤트를 쓰면 호출 시점 고정 규칙을 따른다.
- 위치 0개는 정상적인 ‘호출 없음’이다. 없는 기믹/출력 키, 비활성 기믹, 다른 페이즈 연결은 0개로 무시하지 않고 오류로 알린다.
- 호출 구간 종료, 부모 패턴 취소, 페이즈 전환, 사망/재시작에는 모든 자식 자원을 정리한다. 부모 공격만 취소하는 것은 씨앗 기믹 자체를 없애지 않는다. 광폭화는 같은 페이즈 상태이므로 공격을 유지한다.
- 서로 다른 호출 이벤트의 범위가 겹친다고 하나로 합치지는 않는다. 씨앗 수만큼 공격/VFX가 늘어나므로 넓은 공격과 무거운 효과의 성능·회피 가능성을 확인한다. 대상을 임의 개수로 자르는 제한은 넣지 않았다.
- 자식의 ‘자동 실행 조건’은 직접 호출을 막지 않는다. 광폭화 전후 선택은 부모의 자동 실행 조건으로 구성한다.

## 기믹 합동 미리보기

직접 또는 하위 패턴에 기믹 호출이 있으면 패턴 미리보기에 **기믹 합동 미리보기**가 나타난다.

- **기믹 사전 진행 (초)**: 해당 페이즈의 실제 기믹들을 먼저 진행한 뒤 패턴 0초를 시작한다. 기본 25초, 범위 0~600초. 기본 씨앗은 5초에 생성되어 25초에 처음 완전 성장한다.
- 재사용 패턴에서는 **시험할 페이즈**를 선택한다. 페이즈 패턴은 자신의 페이즈를 사용한다.
- 현재 출력 개수를 기믹별로 표시한다. 이미 진행 중인 공격은 호출 당시 위치를 유지한다. 사전 진행 0초로 씨앗 없는 상태도 시험한다.
- 기본 씨앗의 프리뷰 위치는 초기화 시 재현하도록 난수 시드를 고정한다. 실제 게임과 같은 무작위 결과를 약속하는 기능은 아니다. 미리보기 상태는 에셋에 저장하지 않는다.
- **게임에서 실행**도 해당 페이즈/사전 진행 시간을 사용하며 기믹과 선택 패턴을 함께 실행한다. 사전 진행 중 직접 피해 판정은 억제하고 시작 시 남아 있는 장판/기믹 공격은 이후 정상 작동한다. 기믹 호출 없는 패턴의 기존 단일 실행은 유지한다.
- 합동 미리보기는 선택 패턴과 페이즈 기믹만 실행한다. 정상 전투의 다른 주 패턴/배경까지 모두 실행하지 않는다. 이동 효과·기절과 전체 난이도는 일반 전투에서 추가 확인한다.

## 개발자용 확장

새 기믹은 공개 최상위 `[Serializable]` Definition/Runtime으로 작성한다. 자동 메뉴는 공개 최상위 타입만 수집하여 중첩 테스트 타입을 노출하지 않는다.

1. Definition의 `PositionOutputs`에 안정적인 키와 표시 이름을 선언한다. 표시 이름 변경 시에도 키를 유지한다.
2. Runtime의 `ReadPositions(outputKey)`에서 현재 위치들을 반환한다. 실행 좌표를 에셋에 쓰지 않는다. 없는 키는 base 구현처럼 오류로 처리한다.
3. Session이 `connectionId → Runtime`을 등록하고 `IMechanicOutputHost.CaptureMechanicPositions`로 복사본을 제공한다. 게임/프리뷰는 이 인터페이스만 사용한다. 새 기믹을 추가할 때 호출 이벤트에 타입 분기를 추가하지 않는다.
4. 기믹 내부에서 자동 호출할 패턴이 있다면 Definition의 `ReferencedPatternIds`도 제공한다. 하위 패턴의 활성 페이즈 연결 검증에 사용한다.

기존 클래스에 추가할 예시:

```csharp
// Definition
public override IReadOnlyList<MechanicPositionOutput> PositionOutputs =>
    new[] { new MechanicPositionOutput("charged-devices", "충전된 장치 위치") };

// Runtime
public override IEnumerable<Vector2Int> ReadPositions(string outputKey) =>
    outputKey == "charged-devices"
        ? devices.Where(device => device.Charged).Select(device => device.Cell)
        : base.ReadPositions(outputKey);
```

`connectionId`는 보스 안에서 유일해야 한다. 이름/목록 순서는 식별자가 아니다. 같은 보스에 기믹을 복제하여 ID가 중복되면 오류를 표시한다. 복제본 기믹 화면의 **선택한 기믹의 연결 ID 새로 발급**을 누른 뒤 새 호출 이벤트를 복제본에 다시 연결한다. 다른 보스에 자식 공격을 재사용할 때는 그 보스의 호출 이벤트에서 해당 기믹을 선택한다.

`IEncounterPatternCall`은 일반 보조 호출과 기믹 위치 호출의 공통 참조 계약이다. 기존 재귀/호출 길이/보스 이벤트 검증이 새 호출 경로도 따라간다. 별도 `PatternSequence` 공유 에셋은 보스 로컬 패턴 호출을 지원하지 않으므로 이 이벤트도 사용할 수 없다.

저장된 부패화/골렘에 새 공격을 자동 등록하지 않았다. 실제 검사/미검증 범위는 [현재 패턴 목록](PatternHandoff/CurrentPatternCatalog.md)의 기믹 출력 위치 호출 절에 기록한다.
