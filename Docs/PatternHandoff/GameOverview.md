# 게임 설명 — 패턴 제작 작업 인수인계

기준일: 2026-09-19. 프로젝트: `C:/GameMake/Unity6/LEE`. Unity: **6000.5.3f1**.

2026-09-20 콘텐츠 변경: P1에 주먹 내려치기(`p1-fist-ripple`)와 교차 낙석(`p1-alternating-rockfall`)을 추가해 저장된 주 패턴은 19개(7+12)다. 현재 P1은 사용자 편집으로 기존 5개가 꺼져 두 신규 패턴만 순환한다. 사용자 제공 스프라이트 시트 기반 BossActor/Animator를 함께 사용한다. 아래의 외형 미지정/주 패턴 17개 설명은 최초 인수인계 당시 상태이며, 현재 내용은 [현재 패턴 목록](CurrentPatternCatalog.md)의 전장·패턴·검증 항목을 우선한다.

이 문서는 새 작업자가 게임을 이해하기 위한 설명이다. 구체적인 제작은 [패턴 제작 가이드](PatternAuthoringGuide.md), 현재 저장된 수치는 [현재 패턴 목록](CurrentPatternCatalog.md)을 함께 읽는다. 과거 대화의 NHN 명칭보다 현재 프로젝트 경로와 실제 파일을 기준으로 한다. 이전 채팅을 읽을 수 있다고 가정하지 않는다.

## 1. 어떤 게임인가?

게임 내부 이름은 **Trace Strike**다. 플레이어가 타일 전장에서 보스의 공격을 피하면서 START부터 END까지 경로를 그려 보스에게 피해를 주는 게임이다. 일반적인 액션 게임처럼 공격 버튼으로 보스 몸체를 때리는 구조가 아니다.

한 번의 공격 흐름은 다음과 같다.

1. 초록색 START 타일에 진입하면 경로 기록이 시작된다.
2. 상하좌우로 이동하며 아직 밟지 않은 타일을 연결한다.
3. 주황색 END에 도착하면 자동으로 경로 공격이 발동한다.
4. 기록한 경로의 타일 수에 따라 보스 체력이 감소한다.
5. 새로운 START/END가 생성된다. 플레이어는 기존 위치를 유지한다.

길게 돌아가면 공격력은 커지지만 보스 공격에 노출되는 시간이 늘어난다. 패턴의 목적은 이 **경로 욕심과 생존 사이의 선택**을 만드는 것이다.

## 2. 이동·공격·실패 규칙

| 항목 | 현재 구현 |
|---|---|
| 이동 | 상하좌우 한 칸. 대각선 이동 불가. 바닥 없는 칸과 장애물은 통과 불가 |
| 키보드 | WASD/방향키. 한 번 누를 때 한 칸이며 모든 방향키를 놓아야 다음 입력을 받음. 누르고 있기만 해서는 연속 이동하지 않음 |
| 포인터 | 스와이프/드래그 후 놓았을 때 주된 방향으로 한 칸. 화면 방향 패드도 사용 |
| 경로 중복 | 기록 중 이미 밟은 경로를 다시 밟으면 기록 초기화. 즉사가 아니며 다시 START로 가야 함 |
| 경로 피해 | 일반 타일 1, 논리 격자 중앙 3×3 타일 2. START/END도 기록된 경로에 포함되면 계산 |
| 플레이어 피격 | 현재 보스 공격 피격은 사망 처리. 여러 번 맞는 체력 모델이 아님 |
| 전장 이탈 시도 | 이동 거부. 낙사 처리 아님 |
| 보스 페이즈 | 현재 페이즈 체력 0이면 다음 페이즈, 마지막 페이즈 체력 0이면 클리어 |

중앙 보너스는 보스 외형 위치나 직접 칠한 바닥의 무게중심을 따라가지 않는다. `CombatBalanceRules`가 논리 격자 크기로 계산한다. 바닥이 없는 칸은 당연히 경로에 포함할 수 없다.

POWER/AMPLIFY/MUD/CURSE 관련 예전 코드가 남아 있지만 **현재 일반 전투의 아이템 생성은 꺼져 있다**. `GenerateSpecialTiles()`는 목록을 비우며, 현재 경로 피해 계산도 기본 타일 합계를 사용한다. 이 코드를 보고 아이템 기믹이 일반 전투에서 활성화되어 있다고 판단하지 않는다.

## 3. 보스 공격을 읽는 법

경고 → 타격 → 정리/다음 공격의 시간축으로 설계한다. 한 패턴 안에서 여러 타격을 순서대로, 또는 동시에 배치할 수 있다.

- **Warning**: 위험 위치를 보여 주는 시각적 경고. 자체 피해는 없다.
- **Damage**: 단발 타격. 시작 순간의 플레이어 위치와 `escapeGrace` 뒤 위치를 확인하고, 두 위치 모두 해당 위험 집합 안이면 피격이다. 기본 유예는 0.18초다.
- **Hazard**: 지속 피해 장판. 생성 순간/머무름/진입에 의한 접촉 피해를 만들 때 사용한다.
- **VFX/SFX**: 시각·청각 연출. 이것만 추가해도 피해가 생기는 것은 아니다.

`Damage.duration=0.3`을 3초로 늘려도 3초짜리 접촉 장판이 되지는 않는다. 단발 타격 시작 시 밖에 있던 플레이어는 그 이벤트에 늦게 진입했다는 이유만으로 맞지 않는다. 표시의 지속 시간과 피해 규칙을 분리해서 이해해야 한다.

## 4. 전장과 보스 외형

- 보스마다 전장 크기·바닥 모양·이미지·플레이어 스폰·START/END 생성 가능 영역을 저장한다.
- 크기는 **5~50의 모든 정수**, 최대 50×50. 정사각형 편집 영역에서 바닥을 지워 직사각형/임의 모양을 만든다.
- 전장은 Unity Tilemap 컴포넌트가 아니라 자체 논리 격자와 Canvas UI다. 에디터가 타일맵처럼 칠하기를 제공한다.
- 기본 타일 Sprite를 지정하고 일부 타일만 다른 이미지로 덮어쓸 수 있다.
- 플레이어 스폰과 START는 서로 다른 개념이다. 지정 스폰은 전투 시작/재도전용이며 매 공격 후 돌아가는 위치가 아니다.
- 모든 바닥은 상하좌우로 연결되어야 한다. START/END는 서로 다른 유효 바닥이며 END는 허용 후보 중 START에서 이동 경로가 가장 먼 곳으로 정한다.
- 큰 전장에서는 플레이어 추적 카메라와 미니맵을 사용한다. `cameraZoom`은 표시 배율, `playerSizeRatio`는 타일 대비 플레이어 그림 크기다. 둘 다 논리 이동/피격 칸을 바꾸지 않는다.

고정 보스를 비어 있는 타일 영역에 배치하는 구성은 지원한다. 보스당 **BossActor 프리팹 하나**를 두고 그 안의 Animator 상태를 바꾸는 방식이다. 모션마다 별도 보스 프리팹을 교체하지 않는다. 보스 위치는 타일 중심 기준의 연출 위치이며, 보스 배치 자체가 바닥을 지우거나 이동 충돌을 만들지는 않는다.

현재 저장된 크림슨 골렘에는 BossActor 프리팹이 없다. 중앙을 비우고 보스를 놓는 것은 지원 가능한 제작 방식이지, 현재 에셋에 이미 완성되어 있는 설정은 아니다.

## 5. 데이터와 실행 구조

```text
BossCatalog                         게임에 등록된 보스 / 시작 보스
└─ BossEncounterDefinition          보스 종합 데이터 에셋
   ├─ arena                         맵·이미지·스폰·START/END 영역
   ├─ bossVisual                    보스 외형·배치·기본 애니메이션
   ├─ libraryPatterns               보스 내부 재사용 보조 패턴
   └─ phases[]                      체력·공격 선택·대기 시간
      ├─ patterns[]                 순서대로 또는 무작위로 선택할 패턴
      │  └─ clips[]                 시작 시간 + 지속 시간 + 이벤트
      └─ background                 페이즈 동안 반복할 독립 타임라인
```

보조 패턴은 목록에 있다는 이유만으로 자동 실행되지 않는다. `CallEncounterPatternEvent`로 호출한다. 여러 보스가 공유하는 예외적 패턴만 별도의 `PatternSequence` 에셋에 둔다.

일반 주 공격은 한 패턴이 끝난 뒤 다음 패턴을 고른다. 패턴 내부의 이벤트는 겹칠 수 있고 background는 주 공격과 병렬이다. `shuffle=false`면 저장 목록 순서로 순환하고, true면 실행할 때마다 활성 패턴 중 무작위 선택한다. 중복 없는 셔플 덱은 아니다.

첫 공격 전에는 `initialDelay`, 이후에는 `max(minimumInterval, interval - 완료한 주 패턴 수 × acceleration)`만큼 기다린다. 이 값은 **패턴 시작 간격이 아니라 이전 패턴이 끝난 뒤의 대기 시간**이다.

타임라인과 페이즈 기믹은 scaled time을 사용하며 플레이어의 경로 공격 연출 등 `inputLocked` 동안 멈춘다. 이동만 봉인된 상태와는 다르다. 이펙트 자체 재생까지 모두 같은 시계로 묶인 것은 아니다.

## 6. 현재 콘텐츠의 범위

- BossCatalog에 등록된 보스는 크림슨 골렘 1개다.
- 2개 페이즈, 주 패턴 17개(1페이즈 5개 / 2페이즈 12개), 보조 패턴 2개다.
- 2페이즈는 지정 배치한 통과 가능한 수정 5개를 경로 공격으로 해제하는 기믹을 사용한다. 모두 해제하는 공격까지 보스 체력 1 보호가 유지되고 다음 공격부터 처치할 수 있다. [보스 기믹 가이드](../BossMechanics.md) 참고.
- 보스 전용 애니메이션/모션/VFX 이벤트 타입은 구현되어 있지만 현재 저장 패턴은 아직 사용하지 않는다.
- 허브 관련 코드가 남아 있어도 새 보스를 등록하는 것만으로 허브 선택 화면/잠금 정책까지 자동 확장되지는 않는다.

정확한 전장 좌표와 이벤트 시각은 [현재 패턴 목록](CurrentPatternCatalog.md)에 기록한다. 오래된 생성기 기본값이나 과거 문서의 패턴 개수로 현재 에셋을 재생성하지 않는다.
