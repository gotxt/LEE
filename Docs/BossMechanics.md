# 보스 기믹 — 수정 봉인 제작 가이드

다른 규칙의 기믹을 새 Codex 작업에서 개발하려면 [새 기믹 개발 인수인계](MechanicHandoff/NewMechanicGuide.md)와 [첫 프롬프트](MechanicHandoff/FirstPrompt.md)를 사용한다. 이 문서는 기존 수정 봉인의 사용법과 구현 기록을 설명한다.

## 설계와 확정 규칙

기존 보스 에디터 안에서 페이즈별 기믹을 설정한다. 패턴은 한 번의 공격 시퀀스, 기믹은 페이즈 동안 유지되는 상태와 규칙이다. 보스 이름별 분기나 전용 체크박스를 추가하지 않는다.

크림슨 골렘의 2페이즈에는 `수정 봉인`이 하나 등록되어 있다.

- 페이즈 진입 즉시 지정 위치에 5개 생성. 개수는 배치 목록 길이이며 고정 상수가 아니다.
- 초기 좌표: (17,5), (28,13), (24,27), (10,27), (6,13). 중앙 보스 (17,17)에서 약 12칸 거리의 좌우 대칭 오각형 배치다. 수정 주변 2칸까지 유효 바닥이고 플레이어 시작 위치와 겹치지 않는다. 페이즈 진입 시 이 고정 좌표를 사용하며 에디터에서 변경할 수 있다. 맵/기존 공격은 재생성하지 않았다.
- 수정 타일은 통과 가능하다. 밟기만 하거나 경로를 취소한 경우에는 해제되지 않는다.
- START→END 경로 공격이 확정되면 그 경로에 포함된 활성 수정을 모두 비활성화한다.
- 비활성화 시 해당 수정의 공격과 남은 경고·판정을 취소하고 비활성 외형을 남긴다. 자동 재활성화/체력 절반 재배치는 없다.
- 공격 직전 활성 수정이 하나라도 있었다면 그 공격의 보스 체력 하한은 1이다. **마지막 수정 해제 공격에도 보호가 유지되고, 다음 공격부터 처치할 수 있다.**
- 모두 해제해도 보스가 자동으로 죽거나 체력이 1로 바뀌지는 않는다. 이후에는 일반 피해를 받는다.

## 팀원용 편집 순서

1. `CrimsonGolem` 보스 데이터를 열고 `PHASE 2 → ◆ 수정 봉인`을 선택한다.
2. 오른쪽 `수정 추가`로 바닥을 클릭한다. `선택/이동`은 수정 클릭 후 목적지 클릭, `삭제` 또는 우클릭은 해당 수정 삭제다. Ctrl+Z로 되돌릴 수 있다.
3. `공격 패턴`에서 기존 공격을 선택하거나 `+ 주변 공격 패턴 만들기`를 누른다. 새 공격은 수정 위치 기준 체크무늬 경고/타격으로 시작한다.
4. `공통 공격 편집` 또는 `이 수정의 공격 편집`을 누르면 기존 패턴 에디터로 이동한다. **위치 기준은 `기믹 / 호출 위치`**로 지정한다. 수정의 실제 위치를 원점으로 미리보기하고 타일을 클릭·드래그하여 상대적인 공격 영역을 편집할 수 있다. `기믹 배치로 돌아가기`로 돌아온다.
5. 공통 공격을 수정하면 그것을 공유하는 모든 수정에 적용된다. 하나만 바꾸려면 `이 수정만 별도 공격으로 복제`를 누른 뒤 복사본을 편집한다. 새 ID와 독립적인 이벤트 데이터를 가진 재사용 패턴이 생성된다.
6. `첫 공격 대기`, `반복 주기`를 설정한다. 반복 주기는 **공격 시작부터 다음 공격 시작까지**이며, 공격 전체 길이 이상이어야 한다. 선택 수정의 `개별 시간 사용`으로 따로 지정할 수 있다.
7. 활성/비활성 외형을 지정한다. RectTransform 기반 UI 프리팹 또는 Sprite를 사용한다. 비활성 외형을 비우면 활성 외형을 비활성 색상으로 표시한다. 프리팹이 Sprite보다 우선한다.
8. 상단 `저장`을 누른다. 잘못된 배치·중복 좌표·누락/비활성 패턴·짧은 주기는 오류로 안내하며 실행 전에 검증한다.

초기 공통 공격 `crystal-seal-attack`은 첫 대기 5초, 5초 주기, 수정 주변 2칸 체크무늬(중심 제외), 0.7초 경고, 0.3초 타격(회피 유예 0.18초), VFX_CrystalSparks VFX 0.35초다. 공격 한 회의 전체 길이는 1.05초다. 주 보스 패턴은 별도로 계속 실행된다.

## 미리보기 범위

`기믹 재생`은 선택한 기믹의 모든 수정을 같은 실행 로직으로 시뮬레이션한다. `플레이어` 도구는 경고/회피 판정의 가상 플레이어 위치를 바꾼다. 장치와 타일 이벤트는 색으로 표시하며 실제 외형/효과 확인은 Play Mode에서 한다.

`시험 경로`를 드래그하고 `시험 경로로 공격 (큰 피해)`를 누르면 비활성화와 체력 보호를 시험한다. 이 도구의 타일 집합은 **해제 판정 시험용**이며 START/END와 경로 연결은 검사하지 않는다. 실제 게임에서는 완성된 경로만 전달한다. 모두 해제하는 첫 공격은 1, 다시 공격하면 0이 되어야 한다. 초기화하면 모든 장치와 체력이 복구된다. 시험은 에셋을 변경하지 않는다.

일반 패턴의 단독 미리보기/`게임에서 실행`은 기믹을 자동으로 함께 켜지 않는다. 합동 검증은 정상 전투의 해당 페이즈에서 한다. 경로 공격 연출 중에는 수정 공격도 주 타임라인과 같이 정지한다.

## 개발자 확장 계약

- `BossPhaseDefinition.mechanics`: `[SerializeReference]` 기믹 정의 목록. 정의는 설정만 저장하고 실행 상태는 저장하지 않는다.
- `BossMechanicDefinition`: `[Serializable]`와 공개 기본 생성자를 갖는 새 타입을 추가한다. `Create`, `Validate`, 필요 시 `PlacementCells`를 구현한다. 추가 메뉴는 TypeCache로 발견하며 새 보스마다 중앙 switch를 수정할 필요가 없다.
- `BossMechanicRuntime`: `Advance`, `OnPlayerAttack`, `MinimumBossHealth`, `RequiredCells`, `Status`, `Dispose`를 제공한다. 조건/상태 규칙은 해당 구현이 소유한다. 복잡한 상태 기믹을 거대한 범용 노드 언어로 만들지 않는다.
- `BossMechanicSession`: 여러 기믹의 보호 체력 하한을 합산(최댓값)하고 **해제 전 하한을 저장한 뒤** 경로 반응과 피해를 처리한다. 장치별 `PatternContext`는 서로 다른 origin/자원 소유 범위를 가진다.
- `IMechanicPresentationHost`: 게임과 안전한 에디터 표시를 분리한다. 공격은 기존 `PatternRunner`/`IPatternHost`를 재사용한다.
- 수정 전용 편집 UI는 `BossEncounterEditorWindow.Mechanics.cs`에 분리되어 있다. 새 타입은 기본 SerializedProperty UI로 즉시 표시되며 필요하면 PropertyDrawer나 전용 편집 화면을 추가한다.
- 기믹은 페이즈 시작/전환 때 생성한다. 일반 패턴 교체·배경 패턴 반복은 기믹 상태를 초기화하지 않는다. 사망·클리어·페이즈 전환·재시작·허브/튜토리얼 진입·컴포넌트 종료 때 정리한다.
- 활성 필수 장치 칸은 타임라인 벽 배치에서 제외한다. 기존 전장 연결성/START·END 보호 검사도 유지한다.

`legacyCrystals` 필드는 구 에셋 역직렬화를 위해 숨겨서 보관하지만 정상 전투에서는 사용하지 않는다. 옛 자동 생성·재배치·독립 공격 코루틴은 정상 실행 경로에서 제외했다. 과거 캡처 보조 함수는 일반 기믹 API가 아니므로 새 콘텐츠에서 호출하지 않는다.

확장 시 데이터 직렬화/Undo, 장치별 원점과 시간, 큰 프레임 간격, 여러 기믹의 동시 보호, 마지막 해제 공격, 취소/재시작 자원 정리를 함께 검사한다. 기존 보스 외형/공격 데이터/맵을 수정해 테스트 기대값에 맞추지 않는다.

## 이번 구현의 검증 기록

- Unity 6000.5.3f1 분리 프로젝트에서 관련 9개 테스트 분류 **113개 중 112개 통과**. `Logs/PatternValidation/BossMechanicsRelease.xml` 참고.
- 신규 기믹 검사 **19/19**, 수정 외형/실전 통합 검사 **4/4** 통과. 원점 기준 편집, 직렬화/Undo, 7개 배치, 개별 시간, 여러 그룹, 큰 시간 간격, 마지막 해제 공격, 다음 공격 처치, 경고 취소, 필수 장치 칸의 벽 배치 보호를 검사했다.
- 남은 실패는 `AttackStepEditingTests.ExistingCrossIsRecognizedWithoutChangingData`: 현재 사용자 에셋에 테스트가 찾는 `P1_Cross_0` 표시 이름이 없다. 작업 전 원본 에셋을 별도 프로젝트에 복원해 동일 실패를 확인했다(`BossMechanicsBaseline.xml`). 기존 패턴의 이름/구성을 테스트에 맞춰 변경하지 않았다.
- Sprite 참조 검사는 Play Mode 전환 후 관리 객체가 재생성될 수 있어, 객체 주소 비교 대신 **GUID와 local file ID가 모두 같은지** 검사하도록 보정했다.
- 실제 게임의 활성/비활성 수정과 `0/5 → 5/5`, 체력 `150 → 1` 표시를 자동 렌더 캡처로 확인했다. 입력 경로의 hit-cell 집합을 주입한 전투 검사이며 수동 플레이 난이도 검증은 아니다.
- 정적 에셋 검증과 설치된 Unity 참조 기반 컴파일, `git diff --check` 통과. 사용자 플레이를 통한 배치/공격 난이도, 장시간 성능 및 모든 기존 콘텐츠를 포함한 전체 테스트 실행은 별도다.
